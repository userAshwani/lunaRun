# lunaRun — Build, CI & Release

Related: [ARCHITECTURE](ARCHITECTURE.md) · [REPO-SETUP](REPO-SETUP.md)

**Goal (G4):** one codebase. A pushed version tag makes GitHub Actions build installers for every OS and
attach them to a GitHub Release. Users download from the Releases page, and installed apps update themselves (Phase 2).

## 1. Outputs per release

| OS | Runner | Artifacts |
|---|---|---|
| Windows x64 | `windows-latest` | `lunaRun_<ver>_x64-setup.exe` (NSIS, **per-user install, no admin**), `lunaRun_<ver>_x64_en-US.msi` (optional, for IT deployments) |
| macOS universal | `macos-latest` | `lunaRun_<ver>_universal.dmg` (one build for Apple Silicon + Intel: `--target universal-apple-darwin`) |
| Linux x64 | `ubuntu-22.04` (older glibc = wider compatibility) | `.AppImage`, `.deb` |
| Updater | — | `latest.json` + `.sig` signatures (generated by tauri-action when updater signing keys are set) |

## 2. Versioning

- **SemVer**: `0.y.z` until the first stable release. Tags look like `v0.1.0`, `v0.1.1`, `v0.2.0-beta.1`.
- The version lives in three files that MUST match: `package.json`, `src-tauri/tauri.conf.json` and the root `Cargo.toml`
  (`[workspace.package]`, which every crate inherits). `pnpm bump <version>` (`scripts/bump-version.mjs`) updates all three
  plus `Cargo.lock`, and turns `## [Unreleased]` in `CHANGELOG.md` into `## [<version>] - <date>` with a fresh empty
  Unreleased section above it. Options: `--dry-run`, `--force` (allow a non-greater version), `--no-lock`. It computes every edit
  first, refuses an invalid or non-increasing version or an empty Unreleased section, and restores the files if `cargo update`
  or the final consistency check fails. `scripts/check-versions.mjs` (also used by the release workflow) verifies the result.
- **Conventional Commits** (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `ci:`, `chore:`; `!` for breaking).
  These feed the changelog. Optional later: release-please to automate bumping.
- Pre-release tags (`-alpha`, `-beta`, `-rc`) → the GitHub Release is marked *pre-release*, and only beta-channel users get it as an update.

## 3. Workflows

### `ci.yml` — every push to a PR and to `main`

```
jobs:
  lint:     ubuntu   → pnpm lint, pnpm build (tsc + vite), cargo fmt --check, cargo clippy --workspace --all-targets -D warnings
  test:     ubuntu   → pnpm test (vitest), pnpm build, cargo test --workspace, ts-rs drift check (git status src/bindings must be clean)
  build:    ubuntu   → pnpm tauri build --debug --no-bundle    # whole chain, no LTO, no installer
  test-os:  windows, macos → cargo test --workspace            # workflow_dispatch only while private (D-013)
```

Implemented in `.github/workflows/ci.yml`, with shared setup in `.github/actions/setup/action.yml`
(pnpm from `packageManager`, Node 24, the pinned Rust from `rust-toolchain.toml`, Tauri apt packages).
`pnpm build` runs before every Rust job because the Tauri crate needs `dist/` at compile time.
Pushes that only touch `*.md`, `docs/`, `LICENSE`, `.github/ISSUE_TEMPLATE/` or `.github/dependabot.yml` skip CI.

Use `Swatinem/rust-cache` and pnpm store caching. Concurrency group per branch with `cancel-in-progress: true`.

### `release.yml` ("Build & Release"): tag a release, or press a button

Implemented in `.github/workflows/release.yml`, with three jobs: `plan`, `build`, `publish`.

1. **Plan** (Ubuntu, seconds): runs `node scripts/check-versions.mjs <tag>`, which fails the whole run before any
   expensive build if `package.json`, `src-tauri/tauri.conf.json` and the Cargo workspace version disagree or do not
   equal the tag. It then picks the platforms to build.
2. **Build** (matrix from the plan): `windows-latest`, `macos-latest` (`--target universal-apple-darwin`) and
   `ubuntu-22.04`, each with the shared `.github/actions/setup` action and `tauri-apps/tauri-action@v1`.
3. **Publish** (tags only, and only if every build succeeded): `scripts/finalize-release.mjs` renames the installers
   to the permanent names below and turns the draft into a public release. Until then the release is a hidden
   draft, so a half-finished build never reaches the download page.

**Two ways to use it**

- **Release:** push a tag (`pnpm bump 0.1.0`, commit, `git tag v0.1.0`, `git push origin v0.1.0`). A few minutes later the
  release is public and the README download links serve the new files.
- **Just build:** GitHub > **Actions** > **Build & Release** (click it in the left sidebar; the button is not on the
  "All workflows" list) > **Run workflow**. Pick `all`, `windows`, `macos` or `linux`. The installers are kept as
  downloadable artifacts of that run and no release is created.

**Permanent download names.** Tauri names files with the version (`lunaRun_0.1.0_x64-setup.exe`), but GitHub's
`releases/latest/download/<name>` links need a fixed name. The publish job therefore renames the installers, so the
README never needs an edit:

| Stable name | Platform |
|---|---|
| `lunaRun-windows-x64-setup.exe`, `lunaRun-windows-x64.msi` | Windows 10/11 x64 (per-user NSIS installer, MSI) |
| `lunaRun-macos-universal.dmg`, `lunaRun-macos-universal.app.tar.gz` | macOS 12+, Apple silicon and Intel |
| `lunaRun-linux-x64.AppImage`, `.deb`, `.rpm` | Linux x64 |

The release page itself shows the version (tag and title). If the Phase 2 auto-updater is added, its `latest.json`
must reference these stable names: switch to `releaseAssetNamePattern` in the workflow then. A pre-release tag (one with
a `-`, such as `v0.2.0-beta.1`) is published as a pre-release, which GitHub does not count as "latest", so the
`latest/download` links keep serving the last stable version.

Installers come from the `bundle` section of `tauri.conf.json` (`targets: all`; Windows uses a per-user NSIS
installer, `installMode: currentUser`). Signing secrets are listed in comments in the workflow and are not set yet,
so installers are unsigned until section 4 is done.

**Release procedure:**
1. Make sure `## [Unreleased]` in `CHANGELOG.md` describes the release (the bump refuses an empty section).
   `pnpm bump 0.1.0` → review `git diff` → commit `chore(release): v0.1.0` → push to `main`.
2. `git tag v0.1.0 && git push origin v0.1.0`.
3. Wait for the run (about 12 minutes). If all three builds pass, the release publishes itself and the README links serve it. If one fails, nothing is published: fix it, delete the tag and the draft release (ask first, this rewrites a tag), and tag again.

## 4. Code signing

| OS | Without signing | With signing |
|---|---|---|
| Windows | SmartScreen shows "Windows protected your PC" → *More info → Run anyway*. Works, but scares users. | Azure Trusted Signing (cheapest current option) or an OV/EV certificate. SmartScreen reputation builds over time. |
| macOS | Gatekeeper blocks the app: users must right-click → Open, or run `xattr -dr com.apple.quarantine /Applications/lunaRun.app`. | Apple Developer Program ($99/yr) → Developer ID certificate + notarisation, all handled by tauri-action through the `APPLE_*` secrets. |
| Linux | Not needed | — |

Recommendation: ship private builds unsigned. Before the first **public** release, at least do macOS
notarisation (the unsigned macOS experience is the worst). Document the unsigned workarounds in the README until then.

## 5. Auto-update (Phase 2, FR-AP-05)

- `tauri-plugin-updater`, endpoint: `https://github.com/<owner>/<repo>/releases/latest/download/latest.json`.
- Updates are signed with the **Tauri updater key** (separate from OS code signing). Generate it once:
  `pnpm tauri signer generate -w ~/.tauri/lunarun.key` → put the private key + password in repo secrets, and the public key in `tauri.conf.json`.
  **Back up the private key** (password manager). If you lose it, existing installs can never auto-update again.
- The app checks on launch and every 24 h (can be switched off) and shows "Update available → Install & restart". Before restarting, all services are stopped gracefully.

## 6. Public repository notes

The repository is public (since 2026-10-30), which changes what the earlier private-repo plan assumed:

1. **Standard runners are free** for public repositories, so there is no minute budget to protect. CI runs the Rust tests on
   Windows and macOS on every push (D-015, which supersedes D-013), and a full three-platform release costs nothing.
2. **Release downloads are public**, which is what the README download table needs. The Phase 2 auto-updater can now reach
   `latest.json`.
3. **Branch protection and rulesets** are available for free (Settings > Rules). Consider requiring the CI checks on `main`.
4. **Everything in the repo and its history is public**, including commit author emails and local paths that appear in
   docs. Never commit secrets. Dependabot and secret scanning are free on public repos.
5. Workflow runs started by outside contributors' pull requests do not receive secrets, which is the safe default.

## 7. Local builds

```bash
pnpm install
pnpm tauri dev            # dev mode with hot reload
pnpm tauri build          # installer for the current OS only (cross-compiling installers is not supported)
cargo test --workspace
```

Prerequisites: Rust stable (rustup), Node 24 LTS, pnpm, and the platform toolchain (Windows: VS Build Tools "Desktop development with C++" + WebView2;
macOS: Xcode Command Line Tools; Linux: webkit2gtk-4.1 dev packages). Phase 0 adds these to `CONTRIBUTING.md`.
