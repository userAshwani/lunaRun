# lunaRun — Build, CI & Release

Related: [ARCHITECTURE](ARCHITECTURE.md) · [REPO-SETUP](REPO-SETUP.md)

**Goal (G4):** one codebase. A pushed version tag makes GitHub Actions build installers for every OS and
attach them to a GitHub Release. Users download from the Releases page, and installed apps update themselves (Phase 2).

## 1. Outputs per release

| OS | Runner | Artifacts |
|---|---|---|
| Windows x64 | `windows-latest` | `lunaRun_<ver>_x64-setup.exe` (NSIS, **per-user install, no admin**), `lunaRun_<ver>_x64_en-US.msi` (optional, for IT deployments) |
| macOS universal | `macos-latest` | `lunaRun_<ver>_universal.dmg` (one build for Apple Silicon + Intel: `--target universal-apple-darwin`) |
| Linux x64 | `ubuntu-22.04` (older glibc = wider compatibility) | `.AppImage`, `.deb` |
| Updater | — | `latest.json` + `.sig` signatures (generated by tauri-action when updater signing keys are set) |

## 2. Versioning

- **SemVer**: `0.y.z` until the first stable release. Tags look like `v0.1.0`, `v0.1.1`, `v0.2.0-beta.1`.
- The version lives in three files that MUST match: `package.json`, `src-tauri/tauri.conf.json`, `src-tauri/Cargo.toml` (and the workspace crates).
  `scripts/bump-version.ts <new-version>` updates all of them and adds a `CHANGELOG.md` section heading.
- **Conventional Commits** (`feat:`, `fix:`, `docs:`, `refactor:`, `test:`, `ci:`, `chore:`; `!` for breaking).
  These feed the changelog. Optional later: release-please to automate bumping.
- Pre-release tags (`-alpha`, `-beta`, `-rc`) → the GitHub Release is marked *pre-release*, and only beta-channel users get it as an update.

## 3. Workflows

### `ci.yml` — every push to a PR and to `main`

```
jobs:
  lint:     ubuntu   → pnpm lint, prettier --check, cargo fmt --check, cargo clippy --workspace -- -D warnings
  test:     ubuntu   → pnpm test (vitest), cargo test --workspace
  test-os:  windows, macos → cargo test -p luna-core           # only on push to main (saves minutes, see §6)
  build:    ubuntu   → pnpm tauri build --no-bundle            # compiles, no installer
```

Use `Swatinem/rust-cache` and pnpm store caching. Concurrency group per branch with `cancel-in-progress: true`.

### `release.yml` — on push of a tag `v*`

```yaml
on:
  push:
    tags: ['v*']
permissions:
  contents: write
jobs:
  release:
    strategy:
      fail-fast: false
      matrix:
        include:
          - platform: windows-latest
            args: ''
          - platform: macos-latest
            args: '--target universal-apple-darwin'
          - platform: ubuntu-22.04
            args: ''
    runs-on: ${{ matrix.platform }}
    steps:
      - checkout
      - setup pnpm + Node 24 LTS
      - setup Rust stable (+ targets aarch64-apple-darwin,x86_64-apple-darwin on macOS)
      - linux only: apt install libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf
      - pnpm install --frozen-lockfile
      - verify tag == version in package.json / tauri.conf.json / Cargo.toml (fail otherwise)
      - uses: tauri-apps/tauri-action@v0   # check for the current major version
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          TAURI_SIGNING_PRIVATE_KEY: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY }}
          TAURI_SIGNING_PRIVATE_KEY_PASSWORD: ${{ secrets.TAURI_SIGNING_PRIVATE_KEY_PASSWORD }}
          # macOS signing/notarisation (optional until Q4 decided):
          # APPLE_CERTIFICATE, APPLE_CERTIFICATE_PASSWORD, APPLE_SIGNING_IDENTITY,
          # APPLE_ID, APPLE_PASSWORD, APPLE_TEAM_ID
        with:
          tagName: ${{ github.ref_name }}
          releaseName: 'lunaRun ${{ github.ref_name }}'
          releaseBody: 'See CHANGELOG.md'
          releaseDraft: true          # a human reviews and publishes
          prerelease: ${{ contains(github.ref_name, '-') }}
          args: ${{ matrix.args }}
```

**Release procedure:**
1. `pnpm bump 0.1.0` → review `CHANGELOG.md` → commit `chore(release): v0.1.0` → merge to `main`.
2. `git tag v0.1.0 && git push origin v0.1.0`.
3. Wait for all 3 jobs → open the **draft** release → smoke-test the installers → paste changelog → **Publish**.

### `registry.yml` — daily cron (Phase 1/2)
Runs `scripts/registry/generate.ts`, opens a PR in the registry repo when versions change. See [RUNTIMES §5](RUNTIMES.md#5-registry-generation--hosting).

## 4. Code signing

| OS | Without signing | With signing |
|---|---|---|
| Windows | SmartScreen shows "Windows protected your PC" → *More info → Run anyway*. Works, but scares users. | Azure Trusted Signing (cheapest current option) or an OV/EV certificate. SmartScreen reputation builds over time. |
| macOS | Gatekeeper blocks the app: users must right-click → Open, or run `xattr -dr com.apple.quarantine /Applications/lunaRun.app`. | Apple Developer Program ($99/yr) → Developer ID certificate + notarisation, all handled by tauri-action through the `APPLE_*` secrets. |
| Linux | Not needed | — |

Recommendation: ship private builds unsigned. Before the first **public** release, at least do macOS
notarisation (the unsigned macOS experience is the worst). Document the unsigned workarounds in the README until then.

## 5. Auto-update (Phase 2, FR-AP-05)

- `tauri-plugin-updater`, endpoint: `https://github.com/<owner>/<repo>/releases/latest/download/latest.json`.
- Updates are signed with the **Tauri updater key** (separate from OS code signing). Generate it once:
  `pnpm tauri signer generate -w ~/.tauri/lunarun.key` → put the private key + password in repo secrets, and the public key in `tauri.conf.json`.
  **Back up the private key** (password manager). If you lose it, existing installs can never auto-update again.
- The app checks on launch and every 24 h (can be switched off) and shows "Update available → Install & restart". Before restarting, all services are stopped gracefully.

## 6. ⚠ Private repository caveats

1. **Release downloads are private.** Only signed-in collaborators can download installers from a private repo's Releases,
   and the auto-updater cannot reach `latest.json`. Public distribution and auto-update start when the repo (or a release-only repo) becomes public.
2. **Actions minutes are limited** on private repos (GitHub Free: a monthly quota; **Windows minutes count ×2 and macOS ×10**. Check current GitHub billing).
   One release builds all three OSes, and the macOS job alone can use well over 100 billed minutes. So:
   - Run full-OS matrices only on `main` / tags, and run PR CI on Ubuntu only.
   - Tag releases sparingly while private. Use `workflow_dispatch` with an OS input to build just one platform for testing.
   - Public repos get standard runners free, so this goes away when you go public.
3. **Branch protection / rulesets** for private repos need a paid GitHub plan. On Free, follow the discipline (PRs into `main`) manually until public.

## 7. Local builds

```bash
pnpm install
pnpm tauri dev            # dev mode with hot reload
pnpm tauri build          # installer for the current OS only (cross-compiling installers is not supported)
cargo test --workspace
```

Prerequisites: Rust stable (rustup), Node 24 LTS, pnpm, and the platform toolchain (Windows: VS Build Tools "Desktop development with C++" + WebView2;
macOS: Xcode Command Line Tools; Linux: webkit2gtk-4.1 dev packages). Phase 0 adds these to `CONTRIBUTING.md`.
